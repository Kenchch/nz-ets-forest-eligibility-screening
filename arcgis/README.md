# ArcGIS Pro wrapper

The `.pyt` toolbox delegates to `ets_screening`; it does not reimplement rules.

## Verification status

The toolbox has been **executed under ArcGIS Pro 3.7 (`arcpy` 3.7)** against the
committed Gisborne inputs, not merely reviewed statically. The run screened all
5,712 LCDB units in 27 seconds and its `candidates.gpkg`, `quarantine.gpkg`,
`summary.csv`, `rule_results.csv`, `width_method_comparison.csv` and
`advisory_candidates.csv` are identical to the ones produced by
`scripts/reproduce.py` — the GeoPackages match by semantic content hash and the
tables match byte for byte.

That verification ran against the rule set at commit `622e3b8`. The toolbox
still only forwards to `run_screening`, so the 2026-09-23 rule revision (sliver
filtering, clip-required overlaps, equivalent-rectangle width and contiguity)
reaches it unchanged, but it has not been re-executed under ArcGIS Pro since.
Expected failures (wrong CRS, invalid geometry, the reject-rate gate, a
non-empty output folder that the tool did not create) are reported with
`arcpy.AddError` rather than as a Python traceback.

Executing it surfaced two defects that static review had missed:

- The output folder was declared `direction="Output"`, so ArcGIS raised
  `ERROR 000725` and refused to run whenever the folder already existed. It is
  now an input folder, because the tool refreshes a results folder in place.
- ArcGIS passes a feature class as a catalog path such as
  `gisborne.gpkg\main.gisborne_candidates`. That path reached GDAL unchanged and
  failed with `No such file or directory`, so the tool could not read a
  GeoPackage at all. `ets_screening.arcgis_paths.split_dataset_path` now splits
  a container workspace from its layer name, covering `.gpkg`, `.gdb`,
  `.sqlite` and `.geodatabase`, and leaving shapefiles and plain paths alone.

One difference from the committed run is expected: the toolbox takes no
review-sample parameter, so it draws the hash-ranked sample from scratch, while
`scripts/reproduce.py` pins the 30 units that the committed imagery cards were
rendered for. The pinned sample cannot be regenerated by the current code: it
was drawn by an earlier sampler (`DataFrame.sample(n=30,
random_state=20260912)` over the then 2,520 clean candidates) that has since
been replaced.

## Python environment

The stock `arcgispro-py3` environment ships `arcpy`, `pandas` and `matplotlib`
but **not** `geopandas`, `shapely`, `pyogrio` or `pyproj`. ESRI treats that
environment as read-only, so clone it before adding anything:

```bat
"%PROGRAMFILES%\ArcGIS\Pro\bin\Python\Scripts\conda-proclone.exe" --name arcgispro-py3-ets
proswap arcgispro-py3-ets
conda install -c conda-forge geopandas pyogrio
pip install -e path\to\nz-ets-forest-eligibility-screening
```

The verification above instead side-loaded the dependencies with
`pip install --target <dir> geopandas pyogrio shapely pyproj` and put `<dir>`
plus this repository's `src` on `PYTHONPATH`, which leaves the ArcGIS
installation untouched. `numpy` and `pandas` must be pruned from that directory
so `arcpy` keeps the versions it was compiled against.

## Use

Add `ets_screening.pyt` to an ArcGIS Pro project and supply three EPSG:2193
polygon inputs plus an output folder. Inputs are never reprojected: a layer in
any other coordinate system is rejected, because the area and width tests are
only defensible in metres.

## Cartographic output

`layout_map_arcgispro.pdf` is an **ArcGIS Pro Layout export**, not a Matplotlib figure.
[`build_layout.py`](build_layout.py) authors it through `arcpy.mp` — maps,
symbology, layout, map frames, legend, scale bar, north arrow and text are all
created in the ArcGIS object model, and the file is written by
`Layout.exportToPDF`, so Pro's own layout engine renders it:

```bat
"%PROGRAMFILES%\ArcGIS\Pro\bin\Python\Scripts\propy.bat" arcgis\build_layout.py
```

The A3 landscape sheet carries the district-wide screening result — committed
`candidates.gpkg` and `quarantine.gpkg` symbolised by `status` over the Gisborne
boundary and DOC public conservation land — plus an inset on one R-02 width
disagreement (`lcdb1000453434`), whose 30 m erosion core survives in six
separate fragments (two larger than 500 m²) while its equivalent-rectangle
width is 22.8 m. The counts and the inset text are read from
`outputs/gisborne/summary.csv` and `findings.json` when the layout is built, so
they cannot go stale after a rule change.
Scale, north arrow, data sources, NZTM2000 / EPSG:2193 and the
screening-not-determination disclaimer are on the sheet.

The script needs only `arcpy`: ArcGIS reads the committed GeoPackages directly,
so the screening dependencies above are not required to produce the map. It
writes an `.aprx` (by default into the temp directory, path printed on exit) —
open that in ArcGIS Pro to adjust the cartography by hand and re-export.

`scripts/reproduce.py` deliberately does **not** refresh this PDF; it would
otherwise overwrite the Pro export with the pipeline's Matplotlib page on every
run. The map remains a portfolio artefact, not an official or MPI product.
